# TrafficView 1.2.0 发行说明

发布日期：2026-11-27
发行产物：`trafficview_1.2.0-1_amd64.deb`

1.2.0 在 1.1.1 的基础上加入 GUI 中英文多语言，并修复了部分发行版上悬浮窗
文字被渲染成符号的乱码问题。

## 本版变化

### 中英文多语言（GUI）

- 新增配置项 `language = "auto" | "zh" | "en"`，默认 `auto`：`LC_ALL` / `LANG`
  以 `zh` 开头时使用中文，其余（含未设置、`C` / `POSIX`）使用英文。
- 覆盖范围：托盘菜单与 tooltip、daemon 阈值告警消息与桌面通知、GTK4 设置界面。
- 设置界面「通用」页新增语言下拉（跟随系统 / 中文 / English）；保存后托盘与
  通知立即生效，设置界面需重新打开窗口。
- 文案集中在 `crates/core/src/i18n.rs` 的静态表（125 条，中英文 key 一一对应）；
  未知 key 回退英文表，仍无则返回 key 本身，不会 panic。
- D-Bus v1：`GetConfig` / `UpdateConfig` 增加 `language` 字段，非法值由
  `Config::validate` 拒绝。`UpdateConfig` 未携带该字段时保留当前值，初始默认为
  `auto`；缺少该字段的旧配置文件同样回退到 `auto`。
- 不翻译：CLI 帮助与输出、README/文档、悬浮窗显示项 label（属于用户配置）。

配置示例：

```toml
language = "auto"   # auto | zh | en
```

### 乱码修复

- 修复在部分发行版（如 Linux Mint）上悬浮窗数字与字母被渲染成 ✚★✓ 等符号的问题。
- 根因：cosmic-text 0.12 的字体回退只接受字重完全相等的字体。原实现请求
  `Weight::MEDIUM`（500），系统缺少 500 字重的无衬线字体时（默认族 `Fira Sans`
  也未安装），回退链全部落空并进入任意字体分支，最终按字体库 ID 选中
  `P052` / `D050000L`（Dingbats 符号字体）。
- 两处绘制路径改用默认字重，回退链恢复正常，命中
  `DejaVu Sans` / `Noto Sans` / `Noto Sans CJK SC`。

### 文档

- README 补充语言配置说明，以及卸载时删除本地配置与历史数据的命令。

## 安装与升级

```bash
sudo dpkg -i trafficview_1.2.0-1_amd64.deb
pkill -f /usr/bin/trafficview; sleep 1
setsid /usr/libexec/trafficview-session >/dev/null 2>&1 &
```

已有配置文件不会被自动改写；缺少 `language` 字段的旧配置按默认 `auto` 处理。
升级后如悬浮窗仍显示旧文字，说明仍在运行旧进程，按上面的命令重启会话进程即可。

## 2026-11-28 更新：Ubuntu / Wayland 修复

发行产物仍为 `trafficview_1.2.0-1_amd64.deb`（重新构建），补充以下修复：

- **Wayland 会话自启动**：会话启动器在 Wayland 下也会拉起悬浮窗。此前只在
  `XDG_SESSION_TYPE=x11` 时启动，Ubuntu GNOME/Wayland 登录后只有 daemon 和托盘，
  看不到悬浮窗。
- **Wayland 悬浮窗拖动（无 Xwayland 时）**：GNOME 等不支持 layer-shell 的桌面使用
  `xdg_toplevel` 降级窗口，绑定 `wl_seat`/`wl_pointer`，左键按下时通过合成器的
  交互式移动（`xdg_toplevel.move` + serial）拖动窗口。
- **GNOME 位置恢复**：GNOME/Mutter 不允许 Wayland 客户端设置窗口坐标，原生降级
  窗口每次启动都会被合成器重新摆放，退出重开后位置丢失。`trafficview overlay
  --session auto` 现在在 GNOME 且存在 Xwayland（`DISPLAY` 可用）时改用 X11 后端，
  悬浮窗位置写入 `overlay.position`，重启后按原坐标恢复；没有 Xwayland 时才退回
  原生 Wayland 窗口。
- **Wayland 单实例**：悬浮窗使用 `com.trafficview.Overlay` 固定总线名，托盘菜单与
  会话自启动同时触发也只保留一个进程。
- **托盘显示/隐藏悬浮窗生效**：daemon 的 `OverlayVisible` 属性此前被 zbus 默认的
  `Lazily` 属性缓存固定为首次读取值，Wayland 悬浮窗既隐藏不了也显示不回来。现在
  关闭该代理的属性缓存，并在每个采样周期复核一次可见性。layer-shell 下隐藏时销毁
  窗口、显示时重建（位置由锚点与 margin 决定）；GNOME 的 `xdg_toplevel` 下客户端
  无法设置坐标，隐藏时保留窗口、只提交一帧全透明内容并清空输入区域，显示时恢复
  输入区域并立即重画，避免合成器重新放置窗口导致位置丢失。
- **Ubuntu 验证**：已在 Ubuntu 26.04 LTS（GNOME 50.1 / Wayland，VirtualBox）验证
  悬浮窗显示、左键拖动、退出重开后位置恢复、会话自启动、托盘与设置界面均正常。
  GNOME 无 `wlr-layer-shell`：存在 Xwayland 时使用 X11 悬浮窗（位置可持久化，
  置顶/穿透沿用 X11 实现）；没有 Xwayland 时降级为普通窗口，位置由合成器决定。
  KDE/wlroots 仍使用 layer-shell。
