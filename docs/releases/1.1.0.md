# TrafficView 1.1.0 发行说明

发布日期：2026-11-26
发行产物：`trafficview_1.1.0-1_amd64.deb`（6.2 MB）

1.1.0 是自 1.0.0 以来首次功能升级，核心是两项新增的悬浮窗显示能力：
CPU 温度与 GPU 使用率 + 温度。两项都以"数据归属于设备本身"的模型落地，避免了
渲染层重复实现传感器识别逻辑。

## 本版变化

### CPU 温度监控

- 新增 hwmon + `/sys/class/thermal` 双来源合并去重；同一 chip 名同时出现在 hwmon
  和 thermal_zone 时优先 hwmon。
- 自动识别规则：Intel `coretemp/Package`、AMD `k10temp/Tdie`（回退 `Tctl`）、
  `zenpower/Tdie`、`x86_pkg_temp`、ARM `cpu_thermal` / `soc_thermal`。
- `overlay.cpu_temp_sensor` 可覆盖默认规则，支持完整 label 精确匹配或子串匹配；
  未命中时回退自动规则。
- D-Bus 新增可选顶层键 `cpu_temp`，JSON 自动序列化；无读数时省略。

### GPU 使用率 + 温度

- `GpuSample` 新增 `temp_celsius: Option<f32>`，温度归属于 GPU 自身，多 GPU 时每卡
  都能带自己的温度。
- AMD 从 `card*/device/hwmon/hwmon*/temp*_input` 读取，label 优先 `edge`，回退
  `junction`、`mem`；读数为毫摄氏度，除以 1000 得摄氏度。该路径与 DRM 卡一一对应，
  多卡不会错配。
- NVIDIA 同时支持 nvidia-smi 第 5 列 `temperature.gpu` 与 NVML 动态符号
  `nvmlDeviceGetTemperature`（`NVML_TEMPERATURE_GPU = 0`）；符号缺失或调用失败时
  温度为 `None`，不影响利用率读取。
- Intel 后端暂无温度采集（`temp_celsius = None`），只显示利用率。
- D-Bus `gpu` / `gpus[]` 字典新增可选键 `temp_celsius`，旧客户端兼容。

### 渲染与显示模板

- 新增内置显示项 `gpu`（主 GPU 利用率）与 `gpu_temp`（温度），`is_available` 按
  `snapshot.gpu` / `gpu.temp_celsius` 判定，无数据时整行隐藏。
- `expand_cpu_temp_template` 泛化为 `expand_temp_template`，同时支持 `{cpu_temp}`
  与 `{gpu_temp}` 占位符；有读数时原样保留模板空白，无读数时温度段为空并自动压缩
  多余间距，避免留下 `CPU 14%  ` 这类尾巴。
- 默认显示项追加 `gpu`（`label = "GPU"`、`format = "{value} {gpu_temp}"`、
  `color = "#B197FC"`），已有配置需手动追加该 TOML 片段。
- 悬浮窗初始窗口尺寸自动估算 GPU 项（与 CPU 温度项一致），避免首帧高度跳变。

### 数据流

```
/sys/class/hwmon ─┐                    AMD: card*/device/hwmon ─┐
                  ├─> collectors 合并去重 ─> Snapshot.temps       │
/sys/class/thermal┘  └─> daemon 解析 ─> Snapshot.cpu_temp        ├─> GpuSample.temp_celsius
                                                                 ▼
                                 render 的 cpu/gpu 项（format 内联温度）
```

## 安装与升级

```bash
sudo dpkg -i trafficview_1.1.0-1_amd64.deb
```

从 1.0.2 升级会保留配置与历史数据。升级后需要手动追加 GPU 显示项（如尚未手动追加
CPU 温度内联配置，也一并追加）：

```toml
# ~/.config/trafficview/config.toml 中 overlay.items 末尾追加
[[overlay.items]]
id = "gpu"
label = "GPU"
unit = "%"
format = "{value}  {gpu_temp}"
color = "#B197FC"
visible = true
```

追加后执行一次 `trafficview config set overlay.cpu_temp_sensor ""` 触发热加载，
无需重启。完整字段说明见 README「主要字段」一节。

## 系统要求

- Linux amd64、X11 图形会话；设置界面需要 GTK4 4.14+ 与 libadwaita 1.5+。
- 本包（1.1.0-1）硬依赖 `libc6 (>= 2.35)`、`libgtk-4-1 (>= 4.0.0)`、
  `libadwaita-1-0 (>= 1.4~beta)`，实测可直接安装的发行版：

  | 发行版 | 状态 | 备注 |
  | --- | --- | --- |
  | Deepin 25 | ✅ | 本机日常使用与构建 |
  | Ubuntu 24.04 LTS | ⚠️ | 依赖满足、可安装，但实测运行不正常，原因待排查，暂不建议使用 |
  | Ubuntu 22.04 LTS | ❌ | libadwaita 只有 1.2.0；核心功能理论上能跑，被 GTK4 依赖卡死 |
  | Debian 12 Bookworm | ❌ | GTK4 / libadwaita 版本偏旧 |
  | Ubuntu 20.04 / Debian 11 | ❌ | libc6 不够（2.31） |

- 包内不含 eBPF/AF_PACKET 特权 helper，选到这些后端时按不可用降级。

## 已知限制

- 悬浮窗仅覆盖 X11，Wayland 会话不会自动启动悬浮窗。
- GPU 温度采集：Intel 后端暂为 `None`；AMD 需要内核驱动提供 hwmon 目录；
  NVIDIA 需要 nvidia-smi 或已安装的驱动（NVML 可选增强）。
- 多 GPU 固定显示 `gpus[0]`；后续如需选择 GPU 可引入配置项。
