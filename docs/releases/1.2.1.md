# TrafficView 1.2.1 发行说明

发布日期：2026-11-28
发行产物：`trafficview_1.2.1-1_amd64.deb`

1.2.1 汇总了 1.2.0 发布后的修复：Wayland 会话下的悬浮窗自启动、拖动、显隐与位置恢复，
悬浮窗布局调整为更宽的双列 4:3 分配，并修正设置界面出现在应用列表中的打包问题。

## 本版变化

### Wayland / GNOME 悬浮窗

- **会话自启动**：会话启动器在 X11 与 Wayland 会话下都会拉起悬浮窗
  （`trafficview overlay --session auto`）。此前只在 `XDG_SESSION_TYPE=x11` 时启动，
  Ubuntu GNOME/Wayland 登录后只有 daemon 和托盘，看不到悬浮窗。
- **降级窗口可拖动**：GNOME 等不支持 layer-shell 的桌面使用 `xdg_toplevel` 降级窗口，
  绑定 `wl_seat` / `wl_pointer`，左键按下时通过合成器的交互式移动
  （`xdg_toplevel.move` + serial）拖动窗口。
- **位置恢复**：GNOME/Mutter 不允许 Wayland 客户端设置窗口坐标，原生降级窗口每次
  启动都会被合成器重新摆放。`--session auto` 现在在 GNOME 且存在 Xwayland
  （`DISPLAY` 可用）时改用 X11 后端，悬浮窗位置写入 `overlay.position`，重启后按原
  坐标恢复；没有 Xwayland 时才退回原生 Wayland 窗口（位置由合成器决定）。
- **单实例保护**：Wayland 悬浮窗使用 `com.trafficview.Overlay` 固定总线名，托盘菜单
  与会话自启动同时触发也只保留一个进程。
- **托盘显示/隐藏生效**：daemon 的 `OverlayVisible` 属性此前被 zbus 默认的 `Lazily`
  属性缓存固定为首次读取值，悬浮窗既隐藏不了也显示不回来。现在关闭该代理的属性
  缓存，并在每个采样周期复核一次可见性。layer-shell 下隐藏时销毁窗口、显示时重建；
  GNOME 的 `xdg_toplevel` 下隐藏时保留窗口、只提交一帧全透明内容并清空输入区域，
  显示时恢复输入区域并立即重画，避免合成器重新放置窗口导致位置丢失。

### 悬浮窗布局

- 双列宽度改为 4:3 分配（左列承载“使用率 + 温度”），基准宽度 232px。
- 文字不再按列宽自动换行：超长文本在列尾裁剪，避免两位数使用率时温度被折到行高
  之外看起来像“消失”。
- 皮肤与显示项配置格式不变，已有配置文件无需改动。

### 打包

- `trafficview-settings.desktop` 增加 `NoDisplay=true`，设置界面不再出现在应用列表，
  仅保留托盘菜单与桌面入口的启动方式。

### 文档

- README 更新 Wayland/GNOME 悬浮窗行为、发行版验证说明与 1.2.1 安装命令。

## 安装与升级

```bash
sudo dpkg -i trafficview_1.2.1-1_amd64.deb
pkill -f /usr/bin/trafficview; sleep 1
setsid /usr/libexec/trafficview-session >/dev/null 2>&1 &
```

升级后如悬浮窗仍显示旧文字或位置未恢复，说明仍在运行旧进程，按上面的命令重启会话
进程即可。已有配置文件不会被自动改写。

## 系统要求

与 1.2.0 相同，详见 [1.2.0 发行说明](1.2.0.md) 与
[1.1.0 发行说明](1.1.0.md) 的发行版支持表。1.2.1 在 Ubuntu 26.04 LTS / amd64 上完成
构建与质量门；Wayland 相关修复已在 Ubuntu 26.04 LTS（GNOME 50.1 / Wayland，VirtualBox）
验证。依赖仍由 `dpkg-shlibdeps` 从构建机二进制推导：

```
libc6 (>= 2.35), libglib2.0-0t64 (>= 2.54.0), libgtk-4-1 (>= 4.0.0),
libadwaita-1-0 (>= 1.4~beta)
```

发布二进制以 glibc 2.35 为目标链接，最高只引用 `GLIBC_2.35` 符号。
