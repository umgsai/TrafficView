# TrafficView：轻量 Linux 桌面流量与系统监控，守护进程 + D-Bus 架构

> **一句话**：一个只读 `/proc` 和 sysfs 的守护进程，通过 D-Bus 对外提供数据；悬浮窗、托盘、命令行和 GTK4 设置界面全部订阅同一份数据，不用各自读系统文件。

---

## 主界面长这样

![悬浮窗 + 托盘](https://你的图床链接/overlay.png)

X11 悬浮窗：上下行速率、CPU 使用率（带内联温度）、内存、GPU 使用率（带内联温度）。可拖动、悬停穿透、调透明度、置顶；浅色壁纸下会自动加深文字对比度。

## 核心特性

### 🪟 悬浮窗

- 上下行速率、CPU、内存、GPU 等多种内置显示项
- **CPU / GPU 温度**自动识别（Intel Package、AMD Tdie/Tctl、x86_pkg_temp、ARM cpu_thermal、AMD hwmon edge/junction/mem、NVIDIA nvidia-smi + NVML）
- 温度可**内联**在 CPU / GPU 行后显示（`CPU 14%  70°C`），也可以单独一行
- 无读数时自动整行隐藏，窗口高度随之收缩
- 皮肤用 TOML 描述，支持阈值变色（`warn` / `crit` 配色）
- 初始窗口按"可选项有读数"估算，避免首帧高度跳变

### 📊 托盘

StatusNotifierItem + DBusMenu：暂停/恢复、显隐悬浮窗、切换网卡、打开设置界面或配置文件、退出。

### 📈 历史统计

SQLite 按分钟 / 日 / 月聚合，`trafficview history today` / `history month` 查看。

### 🔔 告警

阈值 + 持续时间 + 冷却时间 + 静默时段，触发后发送桌面通知。

### 🖥 多前端输出

`text`、`json`、`waybar`、`polybar`、`tmux`，`trafficview status --format waybar` 直接输出。

### ⚙ 设置界面

GTK4 + libadwaita，六个页面：通用 / 网络 / 显示 / 告警 / 历史 / 插件。

## v1.1.0 新亮点

### CPU 温度自动识别 + 配置覆盖

内置规则按优先级命中：

1. `coretemp/Package`
2. `k10temp/Tdie`（回退 `Tctl`）
3. `zenpower/Tdie`
4. `x86_pkg_temp`
5. `cpu_thermal` / `soc_thermal`

hwmon 和 `/sys/class/thermal` 双来源自动合并去重；没命中任何规则时返回 `None`，不拿 NVMe / GPU / 主板温度兜底。

支持配置覆盖：

```toml
[overlay]
cpu_temp_sensor = "k10temp/Tdie"   # 精确 label 或子串均可
```

### GPU 使用率 + 温度

`GpuSample` 新增 `temp_celsius: Option<f32>`，温度归属于 GPU 自身：

- **AMD**：从 `card*/device/hwmon/hwmon*/temp*_input` 读取，label 优先 `edge`，回退 `junction`、`mem`
- **NVIDIA**：nvidia-smi 第 5 列 `temperature.gpu` + NVML 动态符号 `nvmlDeviceGetTemperature`
- **Intel**：暂为 `None`，只显示利用率

D-Bus `gpu` / `gpus[]` 字典新增可选键 `temp_celsius`，旧客户端完全兼容。

### 显示模板泛化

`format` 同时支持 `{cpu_temp}` 和 `{gpu_temp}` 占位符：

```toml
[[overlay.items]]
id = "cpu"
label = "CPU"
format = "{value}  {cpu_temp}"   # 两个空格，让百分比和温度之间有呼吸感

[[overlay.items]]
id = "gpu"
label = "GPU"
format = "{value}  {gpu_temp}"
color = "#B197FC"
visible = true
```

无读数时温度段自动为空并压缩多余空白——不会留下 `CPU 14%  ` 这种尾巴。

## 快速安装

### Debian / Ubuntu

```bash
sudo dpkg -i trafficview_1.1.0-1_amd64.deb
```

安装后 daemon、托盘和悬浮窗（仅 X11）在登录时自动启动，由 `/usr/libexec/trafficview-session` 托管。也可以手动：

```bash
systemctl --user enable --now trafficviewd
nohup /usr/bin/trafficview tray >/dev/null 2>&1 &
nohup /usr/bin/trafficview overlay --session x11 >/dev/null 2>&1 &
```

### 源码构建

```bash
git clone https://github.com/umgsai/TrafficView.git
cd TrafficView
cargo build --workspace --release
cargo build --manifest-path frontends/settings/Cargo.toml   # 设置界面
./packaging/build-deb.sh   # 打 deb 包
```

## 个性化配置示例

`~/.config/trafficview/config.toml`：

```toml
[overlay]
cpu_temp_sensor = ""   # 空值 = 自动识别

[[overlay.items]]
id = "cpu"
label = "CPU"
unit = "%"
format = "{value}  {cpu_temp}"
color = "#FFD43B"
visible = true

[[overlay.items]]
id = "gpu"
label = "GPU"
unit = "%"
format = "{value}  {gpu_temp}"
color = "#B197FC"
visible = true
```

追加配置后执行一次热加载即可生效，**无需重启**：

```bash
trafficview config set overlay.cpu_temp_sensor ""
```

## 架构

```
 /proc, sysfs, netlink
        │
        ▼
  只读守护进程 trafficviewd ─── D-Bus (com.trafficview.Daemon1)
        │                          │
        │                          ├── X11 悬浮窗
        │                          ├── StatusNotifierItem 托盘
        │                          ├── GTK4 设置界面
        │                          └── CLI (status / history / alerts)
        │
        ▼
  SQLite 历史统计 + 阈值告警
```

关键约束：

- 所有采集器只返回 `CollectorStatus { available, reason }`，不伪造零值
- 数据归属于设备：`GpuSample.temp_celsius` 属于 GPU 自身，而不是顶层 `Snapshot.gpu_temp`
- D-Bus 新增字段一律是可选键，旧客户端不受影响
- 所有注释、提交信息、文档均为中文

## 技术栈

- Rust 2021，workspace 10 个 crate
- x11rb（X11）、dbus（D-Bus）、GTK4 + libadwaita（设置界面）
- sqlite / rusqlite（历史统计）
- NVIDIA NVML 动态加载、AMD hwmon sysfs 直读

## 已知限制

- 悬浮窗仅覆盖 X11，Wayland 会话需要合成器支持（waybar / polybar 输出已可用）
- GPU 温度：Intel 后端暂未采集；NVIDIA 需要 nvidia-smi 或驱动（NVML 可选增强）
- 多 GPU 固定显示 `gpus[0]`，后续可加配置选择
