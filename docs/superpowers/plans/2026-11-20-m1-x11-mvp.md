# TrafficView M1 Linux X11 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 XFCE/X11 上交付可常驻使用的 daemon、D-Bus、固定布局悬浮窗、SNI 托盘、TOML 配置和自启动。

**Architecture:** `trafficviewd` 持有唯一采集器和配置状态，以固定周期生成快照并广播 `Sample`；`trafficview overlay` 与 `trafficview tray` 只订阅 D-Bus。X11 使用 ARGB override-redirect 窗口，托盘使用 ksni，二者共享 `trafficview-render` 的 ARGB 绘制逻辑。

**Tech Stack:** M0 + Tokio、zbus 4、serde/TOML、dirs、x11rb、ksni、tiny-skia、cosmic-text、image、tracing。

**前置条件:** M0 全部测试和校准通过。执行环境必须有 Linux session D-Bus；最终验收使用 XFCE 4.18/X11，不能仅用 Xvfb 代替人工交互验收。

## D-Bus v1 冻结契约

```text
BUS:  com.trafficview.Daemon1 (session)
PATH: /com/trafficview/Daemon1
IFACE: com.trafficview.Daemon1

Properties: SampleInterval u, Interfaces as, ActiveInterface s
Methods: GetSnapshot() -> a{sv}, SetActiveInterface(s), SetInterval(u),
         SetOverlayVisible(b), ReloadConfig(), Pause(b), Quit()
Signals: Sample(a{sv}), Alert(sss), InterfacesChanged(as), ConfigChanged()
```

顶层快照必需键为 `ts_ms/net/cpu/mem`，三者中的样本为嵌套 `a{sv}`；`disk/gpu` 是可选键，M1 未采集时直接省略（D-Bus variant 没有 null），`temps/plugin` 为空集合，不能用 `0` 假装已采集。CLI 还原 JSON 时将省略的可选结构表示为 `null`。后续阶段只增加可选键，不重命名或更改已有键单位。

- [ ] **Step 3: 实现调度、接口和 CLI 状态查询**

创建 package `trafficview-daemon`，二进制名为 `trafficviewd`，库名为 `trafficview_daemon`，以便集成测试复用。调度器遵循：

```rust
loop {
    interval.tick().await;
    let now = Instant::now();
    let elapsed = now.duration_since(previous_tick);
    previous_tick = now;
    match sampler.sample(elapsed) {
        Ok(Some(snapshot)) => {
            state.write().await.snapshot = snapshot.clone();
            Daemon1::sample(&signal_context, snapshot.to_dbus()?).await?;
        }
        Ok(None) => tracing::debug!("rebuilding collector baseline"),
        Err(error) => tracing::warn!(%error, "sample failed; daemon remains alive"),
    }
}
```

使用 `zbus::connection::Builder::session()? .name(BUS_NAME)? .serve_at(PATH, Daemon1::new(...))? .build().await?`。名称注册失败时记录已有实例并退出成功，不允许两个采集调度器并行。空 `ActiveInterface` 在 M1 使用 `/proc/net/route` 的默认路由网卡；无默认路由时返回明确错误，M3 再增加多活跃卡速率选择。`SetInterval` 修改配置、重建 Tokio interval、发 `ConfigChanged`，并持久化。`SetOverlayVisible` 只更新并持久化悬浮窗显隐状态，随后广播 `ConfigChanged`，供托盘和 overlay 在同一周期联动。daemon 通过 `read_mem_with_mode(root, config.memory_include_cache)` 读取内存；`ReloadConfig` 后下一帧采用新口径，旧 `read_mem` 保持 false 的 M0 默认行为。

CLI 增加 `trafficview status --json`、`trafficview pause`、`trafficview resume`、`trafficview quit`。`status` 调用 `GetSnapshot()` 后从 D-Bus 字典还原 `Snapshot`，输出紧凑 JSON；暂停时返回错误码 2 和“daemon is paused”，不能输出陈旧快照。

- [ ] **Step 3: 实现渲染与 X11 窗口**

`render` 用 tiny-skia 创建 premultiplied RGBA `Pixmap`，cosmic-text 加载 fontdb 系统字体并启用等宽数字；固定画布局部坐标以 96 DPI 为基准。只暴露 `render(snapshot, config, dpi) -> RenderedFrame { width, height, argb, cache_key }`，不引用 x11rb。

`ui-x11` 使用 x11rb 完成以下路径：

1. 连接 `$DISPLAY`，查询 32-bit ARGB visual；无合成器时回退 24-bit 并记录透明度不可用。
2. 创建 `override_redirect=true`、无边框窗口，设置 `_NET_WM_WINDOW_TYPE_DOCK`、`_NET_WM_STATE_ABOVE` 和 app id。
3. 用 SHM 或 `put_image` 提交 ARGB 帧；格式化文本/cache key 未变化时不提交。
4. 订阅 D-Bus `Sample` 和 `ConfigChanged`，在统一事件循环中处理曝光、拖拽、销毁、RandR 和配置。
5. 鼠标穿透通过 XFixes/Shape 将 input region 设为空；拖拽时暂时关闭穿透，松开保存位置。
6. 读取 `Xft.dpi`，监听 RandR 输出变化，按当前屏幕约束位置。

CLI `trafficview overlay --session x11` 启动该前端；未设置 `$DISPLAY` 时给出明确错误，不能退回读取 `/proc`。
